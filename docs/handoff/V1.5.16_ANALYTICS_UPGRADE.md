## 5. 统计口径

### 5.1 题目表现
- **单位**：`(student_id, question_id)`，不是作答行。
- **当前有效记录**：按 `revision DESC, submit_time DESC, id DESC` 取第一条；同一题在多个测验节点的提交只算一次。
- **应作答**：题目在题单内时，= 参与该题所属节点的学生集合（可按班级过滤）；题单外 → `expected=0`，作答计入 `out_of_scope_answered`；没有题单数据 → `expected=null`、`expected_basis=uncomputable`，不伪造。
- **实际作答**：至少有一条答案或过程非空的提交记录的学生数。
- **互斥分区**：`answered = graded + review + failed + pending`；`expected = in_scope_answered + not_answered`。
- **平均分/得分率**：只对 `graded` 的当前有效记录按学生等权计算；满分不一致时给出 `max_score_consistent=false`。
- **修订/重复**：`revision` 多条只取最新；同一学生跨节点同题只算一次。

### 5.2 班级掌握分布
- 状态沿用 `熟练掌握 / 基本掌握 / 初步掌握 / 掌握不足 / 证据不足`，阈值不变（`MIN_EVIDENCE=2`、`MIN_QUESTIONS=2`、`MIN_COVERAGE=0.25`，可环境变量覆盖）。
- 每个知识点输出 `status_breakdown`（人数、占比、学生名单），并校验 `sum(count)=全班人数`（`status_total_check`）。
- 均值与标准差只使用达到证据门槛的学生；证据不足不按 0 分。

### 5.3 班级比较
- `difference = max(mean) - min(mean)`，`pp_difference = difference × 100`。
- 行按 `|pp_difference|` 降序；优势 = 差值 ≥ 10pp；共同薄弱 = 所有班均值 < 0.65；样本不足 = 任一班有效学生 < 3（`XUEBAN_COMPARE_MIN_SAMPLE`）或没有估计。
- 覆盖率低于 30% 时提示 `coverage_warning`，不把它解释为显著差异。

### 5.4 学生画像数据范围
- 全局范围：单次任务 / 全部任务 / 多次任务；学生页不再有独立开关。
- 跨任务合并前校验：知识点映射版本、重叠题目的满分与评分点定义、评分规则/课程标准版本；不满足且没有 `teacher_version_compat` 登记的任务进入 `excluded_batches` 并附原因。
- 趋势只使用可比任务；不可比任务不补 0、不参与 EWMA。

### 5.5 证据聚合
- 同一题多个评分点映射同一知识点：先按题聚合，Beta 权重之和不变；`evidence_count` 改为独立题目数，`evidence_point_count` 保留评分点行数。
- 修订版本只取当前版本。
- 低置信度（< 0.5）错误标签不进入确定性错误统计，保留原始标签与置信度。
- 错误频次：`occurrences` 1 → 单次、2–3 → 重复、≥4 → 高频。

## 6. 自动分析流水线

1. **触发**：判题 job 进入 `completed/partially_failed/failed` 后调用 `refresh_analysis(..., include_llm=True)`；人工修正、评分点确认、单题判题、重解析只刷新确定性统计（避免每次编辑都调用模型）。手动「刷新分析」和首次打开缺结果时，接口先入队并立即返回 `pending`，由后台线程执行，前端轮询 `running → completed`。
2. **确定性层**（不调用模型）：批次汇总、每班 `class_profile`、`question_performance`，写入 `result_json`。
3. **LLM 层**：单独任务，输入是确定性摘要 + 可引用 ID（`evidence_digest`），输出 `class_observations` / `error_explanations` / `teaching_suggestions`，保存 `model`、`prompt_version`、`generated_at`；不重算数字。
4. **状态**：pending → running → completed / partial / failed；`step`、`progress`、`error` 持久化；前端轮询真实状态。
5. **幂等**：`dedupe_key = hash(batch, scope, scope_id, kind, data_version, pipeline_version)`；重复触发复用；`force` 在无运行中任务时原地重置。
6. **失效**：`data_version` 由判题 run 数/时间、修正数/时间、评分点确认数/时间、映射版本、算法版本组成；变化后旧任务 `stale=true`，页面打开时自动重建。
7. **恢复**：任务落库，刷新/离开页面再返回仍能读到同一任务与结果。

## 10. 未验证 / 已知限制

1. **应作答的精确度**：CSV 没有逐生题单，当前按「参与节点 ∩ 班级题单」计算；若老师需要「每生应做哪些题」，需要提供逐生题单（表结构已支持，`student_id` 字段）。
2. **LLM 质量**：真实调用成功并引用证据，但没有人工评测集（`error_label_gold=0`），不能报告语义分析的准确率；LLM 调用会产生费用与延迟（本次一次约 30s）。
3. **长任务进度**：确定性批次任务约 8–9s，进度只到 10%/100% 两档；没有细粒度子步骤进度。
4. **后台执行模型**：LLM 用进程内 daemon 线程，进程重启会丢失运行中的任务（状态会停在 running，需手动重试）；没有独立队列/worker。
5. **趋势样本**：当前两批数据同源，趋势的可比性分支只在小样本单测里覆盖，真实数据还不足以产生两个独立可比时间点。
6. **164 个历史 pytest 模块**仍不可运行（环境没有 pytest）；本次全部用 unittest。
7. `teacher_analysis_tasks.result_json` 单条可达 1.2MB（批次快照），未做压缩/分页；后续数据量增大需要拆表或落对象存储。
