## 2. 判题数据流

见 `V1.5.13_FULL_GRADING_ADMISSION.md` 第 1 节。关键点：

- 原始 CSV → `teacher_answers`（原样保留 raw_json/solution_process/revision/version_id）。
- 题面/参考答案/解析/满分/评分点 → `teacher_question_versions`；缺失才 `global_fallback`，记录 `question_source`。
- `build_source_steps` 生成带偏移的 source_step；模型拆分 reasoning_step/operation_unit。
- `validate_llm_result` 做三层关联、评分点闭包、知识来源标记。
- `insert_grade` 持久化 `step_results_json`、`structure_json`、`request_context_json`、`raw_response`。
- 每次判题 `grading_version+1`；历史 run/人工修正/评分点确认不覆盖。

## 3. 字段与关系

详见准入报告第 2/3 节。

```text
source_step → reasoning_step → operation_unit
                    ├── scoring_point_link（分值/证据）
                    └── knowledge_link（来源/置信度/映射版本/确认状态）
```

- source_step 有 `src-N`、原文、start/end offset，可回切 `solution_process`。
- reasoning 必须有有效 source；无效时置空并 review，不伪造。
- operation 必须绑定 reasoning/source；同一 source 可多个 reasoning，同一 reasoning 可多个 operation。
- 评分点可多证据，但累计只计一次且不超原始满分。

## 4. 评分闭合规则与证据

规则见准入报告第 4 节。测试证据：

- 步骤分/操作分/总分/满分逐层校验；不一致 → review。
- 未知评分点、超分 → ValueError（整题失败，不写有效分）。
- 未处置评分点 → `unaddressed_scoring_points` + review，不按 0 分。
- 评分点文本无法解析 → 空 + review/预检，不猜测。
- 同一评分点两条证据：累计 2/3，evidence_count=2，未重复计分。

证据追溯示例：`verify-artifacts/v1.5.13/structure_example.json`（source src-1/src-2 → rs-1/rs-2 → op-1-1… → Q001P1/P2 → I01 pending）。

## 5. 数据库结构变化

- `teacher_grade_runs.structure_json TEXT`：source_steps、validation、issues、scoring_points、context_warnings。
- `teacher_grade_runs.request_context_json TEXT`：题目版本/来源、标准、教材、模型、prompt/grader、mapping_version、source_step 数。
- `teacher_grade_attempts.grading_version INTEGER`：attempt 与 grading_version 分离；`attempt_number` 按 answer+job 递增。
- `init()` 自动补列；正式库尚未迁移 v1–v5（见 v1.5.12 报告）。
