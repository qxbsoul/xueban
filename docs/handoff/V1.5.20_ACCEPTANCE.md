## 2. 根因与修改（逐项）

### 2.1 预处理卡片与异常 26 / 明细 9
**根因**：
- 27 条异常是「异常作答记录数」；9 条是 `detected+pending_review` 的「问题记录数」。二者单位不同。
- `/issues?status=pending` 只返回未处理问题，不能下钻「已接受/已解决/已排除」问题，也不能按作答记录查看全部关联问题。
- 前端把 `pending_issues` 当作异常明细入口，导致 26 条异常只能看到 9 条问题。

**修改**：
- 卡片删除「状态合计/总数对账/一致·不一致」，只保留原始/有效/异常/需人工核实；后端保留 `reconciled` 校验，不一致写 `logger.error` 并在报告写 `consistency_warning`，不把内部指标塞回教师主界面。
- 新增 `GET /batches/{id}/preprocess-records`：按**作答记录**分页（学生+题目+版本+事件），每条返回全部关联问题；支持 `state` 与 `issue_status` 筛选（全部/待处理/待复核/已接受/已自动规范化/已解决/已排除）。
- UI 明确标注「异常作答记录」「需人工核实记录」「待处理问题记录（与异常作答记录不是同一单位）」；「加载更多」改为追加而不是替换，26 条可全部下钻。
- 记录头展示学生、班级、题目、`r版本 · 事件编号`；问题展示类型、字段（按问题类型映射）、原始值、期望值、原因、检测规则、处理状态、处理结果。
- 一条作答多个问题只算 1 条异常记录；问题详情内逐条列出，不重复计数。

真实数据：`raw 806 = 有效 775 + 异常 26 + 需人工核实 5`；异常记录 26 条全部可下钻；待处理问题 9 条；示例 `scoring_points_sum_mismatch`：原始值 5.0 / 期望值 3.0 / 规则 `sum(score in scoring_points) != question_version.max_score`。

### 2.2 「待确认」语义
- 前端统一改名 **需人工核实**；与「判题待复核」「尚未判题」分开：前者是数据问题，第二是模型判题结果待复核，第三是尚未产生判题结果。
- 进入需人工核实必须有具体原因：空答案且无法判定、过程要求未知、待复核问题、修订冲突等。
- 只需答案的选择/判断/填空缺过程**不进入**需人工核实，只在质量标记里提示。
- 要求过程的题缺过程 → 保留有效、允许整题判断，标记「分步证据不足」提醒。
- 未知题型缺过程 → 需人工核实，并说明「该题题型为空，无法确定是否要求过程」。
- 知识点映射缺失/未映射评分点 → 问题类型为 `missing_knowledge_mapping`/`unmapped_scoring_point`，归类为映射问题，不冒充学生作答异常。
- 评分点异常显示原始值/期望值/规则/处理状态；字段由问题类型映射（如 `scoring_points`、`original_score`）。

### 2.3 学情分析每次进入重新生成
**根因**：`analysis_overview` 每次请求重新计算全部班级画像；`analysis_class` 每次重新 `class_profile` 并写快照；`analysis_student` 每次重算；没有读取 `teacher_analysis_tasks.result_json`；前端也没有使用确定性缓存。

**修改**：
- `analysis_pipeline.get_deterministic(batch, scope, scope_id)`：按 `data_version` 读取已完成的确定性任务结果，没有才生成一次并持久化；同一版本重复进入直接复用。
- `analysis_overview` 使用 batch 级缓存（一次得到所有班级 profile），`analysis_class` 使用 class 级缓存，`analysis_student` 使用 student 级缓存。
- `data_version` 包含判题版本、人工确认、映射版本、算法版本；`evidence_version` 增加映射版本。算法升级到 `sp-beta-v4`，旧缓存自动失效而非误用。
- 语义分析仍只读 `latest_valid_llm`；有成功结果时不会因刷新/切页再次调用模型；失败任务不覆盖旧有效结果，新成功后才 supersede。
- 映射修改：`POST /scoring-points/{sp}/knowledge-links` 只对使用该评分点的作答记录 `mapping_changed` 事件，按学生/班级失效，随后 `refresh_analysis(include_llm=True)`。
- 失败重判继续沿用原 job；成功后 grade 事件 + job 结束 `refresh_analysis`，只更新受影响学生/班级。

### 2.4 1107 / 399 / 708
**根因**：
- `teacher_question_assignments` 只有班级级行，来源是 `teacher_exams.available_questions`（27/45 题池），没有逐生题单。
- `question_performance` 把「题目池 × 节点参与学生」当成应作答，得出 1107；再用 1107-399 得出 708，属于**推算出来的未提交**，不是真实缺交。
- N01/N02 是随机抽测节点，不是题组；同一题可在两个节点出现，修订版本也不能重复计。

**修改**：
- 只有逐生题单（student_map）或明确班级题单（source != exam_available）才计算 `expected`；否则 `expected=None`、`basis=unknown`，只给 `pool_reference`（题目池参考，明确不是应作答）。
- `confirmed_unsubmitted` 只统计 `score_status` 明确为 `unanswered/unsubmitted/未提交`；空记录但无标记归为「无法确定」。
- 实际提交按学生+题目+任务去重，修订记录只取最新；不同班级隔离；超出题目池的作答进入 `out_of_scope`，不混入应作答。
- 班级卡片和题目表拆成：应作答组合数（无法确定）、实际提交、成功、待复核、失败、未判、确认未提交、无法确定范围（题数）、题目池参考。
- 新增单题 `scope/lists`：统计范围、依据、实际提交/成功/复核/失败/未判/确认未提交/未作答/超出题目池名单，前端抽屉可查看。

真实 DC01：`应作答=无法确定`；`题目池参考=1107`；`实际提交=399`；`成功330/复核61/失败8/未判0`；`确认未提交=3`；`无法确定范围=54 题`。旧的 708 不再展示，也不作为真实缺交。

### 2.6 正确答案显示「无法确定」
**根因**：`_evidence` 和 `question_performance` 直接拿整题/步骤错误标签覆盖所有评分点；满分评分点也被标成未知。

**修改**：
- 以评分点为单位：`awarded >= full` → `正确`；否则规范化错误标签；无可靠标签 → `未识别错误`。
- 统一六类：概念理解错误、方法选择错误、推理过程错误、计算操作错误、表达规范错误、未识别错误；旧标签（公式使用错误、步骤遗漏、符号表达、单位格式等）确定性映射。
- 低置信度（< `ERROR_MIN_CONFIDENCE`）不进入确定性分类，保留 `error_label_raw/confidence`，显示未识别错误。
- 判题失败不生成错误证据；待复核不进入确定性错误统计。
- 班级/学生/知识点错误统计共用同一 `_canonical_error` 与 `ERROR_TAXONOMY`。

### 2.7 顶部数据范围
- 合并为一个 `.ta-scope` 组件：分段按钮「本次任务/全部任务」+ 仅本次任务显示具体任务下拉。
- 切换范围/任务时清空班级、学生、知识点详情、题目抽屉；默认最新任务；所有子页面共用同一 `scope/batchId` 状态。
- 浏览器验证：全部任务时 select 数 0，本次任务时 1；切换后无旧详情残留。

### 2.8 学案课程

  - **导入已有学案**：单入口拖拽/点击选择 Markdown，选择后自动导入，无第二个「导入」按钮；显示上传/导入进度、成功字数、失败原因；成功后刷新课程列表。
- 保留原课程列表、教材详情、章节、共享全部学生逻辑。
- 修复文件选择 FileList 被立即清空导致列表为空的问题（先 `Array.from` 再清空 input）。

### 2.9 136 条判题失败
