## 1. 判题完整数据流

```text
原始 CSV
  → teacher_answers（原始作答/过程/raw_json/event/revision/version_id）
  → teacher_question_versions（题面/参考答案/解析/满分/评分点/知识主题）
  → teacher_meta（版本优先；缺失才 global_fallback，并记录 question_source）
  → build_source_steps（原文片段 + 偏移，src-N）
  → llm_grade（注入 source_steps/课程标准/教材上下文；prompt v4）
  → validate_llm_result（source→reasoning→operation；评分点闭包；知识关联）
  → insert_grade（step_results_json + structure_json + request_context_json + raw_response）
  → teacher_grade_runs（grading_version 递增，历史保留）
  → teacher_grade_attempts（job/answer/revision/grading_version/attempt_number）
  → teacher_grade_job_items（原子领取、状态、grade_id）
  → 学情分析（只使用 graded/manual_confirmed/manual_corrected）
  → 人工确认/修正（teacher_corrections、评分点确认历史；原始 AI 结果不覆盖）
```

## 2. 数据字段清单（新增/关键）

`teacher_grade_runs`：

- `grading_version`：同一作答每次判题递增，旧结果保留。
- `question_version_id`：本次实际使用的题目版本。
- `grading_model`、`grading_prompt_version`（v4）、`grader_version`（v1.5.13）。
- `mapping_version`：本次使用的评分点映射版本。
- `standard_id/standard_version/scoring_rule_version`。
- `textbook_course_id/textbook_unit_id/textbook_context`。
- `step_results_json`：reasoning_step + operation_unit + scoring_point_links + knowledge_links + evidence_text。
- `structure_json`：`source_steps`、`validation`、`validation_issues`、`scoring_points`、`unaddressed_scoring_points`、`context_warnings`。
- `request_context_json`：题目版本/来源、标准、教材、模型、提示词、评分器、映射版本、source_step 数、上下文警告。
- `raw_response`：模型原始响应（JSON 文本）。

`teacher_grade_attempts`：

- `task_id/job_id`、`answer_id`、`batch_id`、`student_id`、`question_id`、`event_id`、`revision`。
- `attempt_number`（同一 answer+job 递增）、`grading_version`、`model`、`prompt_version`、起止时间、failure_stage、error、retryable、result_id、duration_ms。

三层结构（存于 step_results/structure）：

- `source_step`：`source_step_id/src-1..N`、source_order、original_text、start_offset、end_offset。
- `reasoning_step`：`reasoning_step_id`、source_step_id、step_index、student_step、normalized_step、expected_step、reasoning_purpose、operation_type、prerequisite_steps、is_correct、score、max_score、error_type、judgment_reason、confidence、evidence_text、scoring_point_links、knowledge_links。
- `operation_unit`：`operation_id`、reasoning_step_id、source_step_id、operation_index、student_fragment、normalized_operation、expected_operation、operation_type、reasoning_purpose、prerequisite_operations、is_correct、score、max_score、error_type、judgment_reason、confidence、evidence_text、scoring_point_links、knowledge_links。

## 3. 结构关系

```text
source_step (原文片段，可回查 solution_process 偏移)
   └── reasoning_step (1..N，每个必须绑定有效 source_step)
          └── operation_unit (1..N，每个必须绑定 reasoning_step)
                 └── scoring_point_link (评分点/得分/满分/证据)
                 └── knowledge_link (知识点/来源/置信度/映射版本/确认状态)
```

- 同一 source_step 可以产生多个 reasoning_step；同一 reasoning_step 可以拆多个 operation_unit。
- 无法可靠拆分时返回空并标记 `needs_review`，不伪造步骤。
- 模型未返回有效 `source_step_id` 时保存 `null` 并记录 `reasoning_step_without_source`，不强行映射。

## 4. 评分闭合校验

`validate_llm_result` 现在执行：

1. 总分 0..题目满分；步骤分 0..步骤满分；操作分 0..操作满分。
2. 步骤分合计 == 总分；操作分合计 == 步骤分（不一致 → needs_review + issue）。
3. 步骤满分合计 == 题目满分（不一致 → review）。
4. 评分点必须来自当前题目版本的原始评分点；不认识 → ValueError。
5. 每个评分点分值不得超过其原始满分；同一评分点可多证据，但累计只算一次且不得超上限。
6. 评分点得分合计 == 总分（不一致 → review，绝不静默）。
7. 未处置评分点列入 `unaddressed_scoring_points` 并 review；不把缺失当 0 分。
8. 评分点原始文本无法解析为结构化分值时，`scoring_points` 为空并标记 review/预检，不猜测。

评分点解析兼容真实格式（如“Q015P1 正确去分母 1分”），并避免把解析式中的 `-9` 误当分值。

## 9. 预计 API 调用与费用

- 预计调用：**699 次**（227 直接 + 472 需复核），不含失败重试。
- 重试上限：若 10% 失败并各重试一次，约 +70 次；实际以失败率计。
- 费用：**无法准确估算**。取决于每题 token（题面+过程+参考+教材上下文+JSON 响应）与 DeepSeek 当前单价；服务端未保存 token 计量，预算需按实际样本先跑 10–20 条测量。
- 建议：先用 10–20 条真实样本测量平均 token 和耗时，再决定批次与暂停点。

## 10. 暂停、恢复、重试与回滚

- 暂停：`POST /grade/jobs/{id}/pause`；运行中心跳未过期的 worker 会完成当前 item 后停止领取；排队/心跳过期直接 paused。
- 恢复：同一 `job_id`，`resume` 置 queued 并重新调度；不创建新 job。
- 失败重试：只重置 `status='failed'` 的 item；`needs_review` 不自动重试；attempt 累加，grading_version 递增。
- 不覆盖历史：每次判题新增 run；旧 run、人工修正、评分点确认全部保留。
- 回滚：判题结果不能“批量删除”来回滚；如需撤销，保留历史并新增人工修正/重判；数据库级回滚只用于迁移失败，按 v1.5.12 备份恢复。
