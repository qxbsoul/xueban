# v1.5.13 变更说明：判题结构、评分闭合与证据链

基线：v1.5.12 `d9dffe9`。本版本不新增学情功能，集中修复判题数据结构、评分闭合、证据链和全量准入。

## P0 三层步骤结构

- 新增 `build_source_steps()`：把 `solution_process` 切成可定位的 source_step（`src-N`、原文、start/end offset），只作为证据片段，**不再把换行当数学步骤**。
- 模型提示词升级为 `teacher-grade-v4`：要求返回 `reasoning_step_id`、`source_step_id`、`evidence_text`、`operation_units`、`knowledge_links`。
- `validate_llm_result` 现在输出/校验：
  - source_step → reasoning_step → operation_unit 三层；
  - 每个 reasoning 必须有有效 source（无效则置空 + review，不伪造）；
  - operation 必须绑定 reasoning 与 source；
  - operation 分合计必须等于步骤分（不一致 review）；
  - reasoning/operation ID 稳定且不重复。
- `insert_grade` 新增 `structure_json`（source_steps/validation/issues/scoring_points/context_warnings）与 `request_context_json`（版本、模型、提示词、教材、映射版本等）。
- 旧判题的 `structure_json` 为 NULL，不重写；预检标记为历史结构缺失。

## P0 评分点闭合

- `parse_scoring_points()` 读取题目版本真实评分点分值，兼容“Q015P1 描述 1分”，避免把描述中的 `-9` 误当分值。
- 评分点必须属于当前题目版本的原始评分点；不认识的评分点直接拒绝。
- 同一评分点允许多个证据片段，但累计只计一次且不得超过其原始满分。
- 评分点合计与总分不一致 → review，不静默通过；未处置评分点单列，不按 0 分。
- 步骤分/操作分/总分/满分逐层校验；步骤满分合计与题目满分不一致 → review。
- 评分点原始文本无法结构化 → `scoring_points` 为空并 review/预检，不猜测。

## P0 知识点关联

- 每个 reasoning/operation 支持 `knowledge_links`，字段：knowledge_point_id、relation_type、source_type、confidence、mapping_version、confirmation_status。
- 模型推断默认 `source_type=model_inferred`、`confirmation_status=pending`，不会自动变成教师确认。
- 未知知识点保留并标记 `unknown_knowledge_point`，不强行丢弃或补全。
- 映射版本取 `analysis.current_mapping_version(batch)`；历史映射变化不会回写旧 grade 的 structure。

## P0 证据链与上下文

- 保留 `raw_response`；新增 `request_context_json`，记录 question_version_id、question_source、standard、教材、model、prompt、grader、mapping_version、source_step 数、context_warnings。
- `answer_detail`/`results` 返回 `structure_json`、`request_context_json`，可逐层追溯。
- 缺失标准/教材/题目版本会记录 `context_warnings`；全局题表回退自动 `needs_review` + `global_question_fallback`。

## P0 状态、计数与人工确认

- `failed` 不再写 `needs_review=1`；失败与待复核分开。
- 新增 `sync_job_counts()`：暂停/恢复/重试时用 item 状态重算 `processed=completed+failed`，修复历史 `processed=805` 与 `completed+failed=104` 不一致。
- job 详情返回 `counts` 与 `processed_consistent`。
- 人工整题确认：若 structure 有 review 问题，返回 409，必须逐点确认或人工修正；强制确认需 `force=true` + 理由并留痕。
- 评分点确认：未确认全部评分点时保持 `needs_review`，即使已确认部分合计等于总分；返回 `fully_confirmed`/`total_points`。
- 人工改总分：在 structure 记录 `manual_override`（总分、评分点合计、points_synced），不覆盖原始 AI 结果。
- 重试仍只处理 failed，不重试 needs_review；attempt 记录 `grading_version` 与递增 `attempt_number`。

## P1 全量准入工具

- 新增只读 `scripts/full_grading_preflight.py`：20 项检查、按 answer 输出异常、分类为直接/需复核/阻断/仅分析、job 状态、映射、API 配置、预计调用数。
- 结果：`verify-artifacts/v1.5.13/full_grading_preflight.json` / `full_grading_anomalies.csv`。
- 真实数据：806 作答，105 已判，701 待判，227 直接，472 需复核，2 阻断；90 legacy 映射；无 API Key。
- 未调用模型、未改正式库。

## 数据库变化

- `teacher_grade_runs.structure_json TEXT`
- `teacher_grade_runs.request_context_json TEXT`
- `teacher_grade_attempts.grading_version INTEGER`
- 旧库由 `init()` 自动补列；正式库尚未迁移 v1–v5（见 v1.5.12 迁移报告）。
