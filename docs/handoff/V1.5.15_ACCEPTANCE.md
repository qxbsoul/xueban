## 1. 根因（最重要）

对正式库只读审计（批次 `batch_a76e3dd0aa`）：

```text
作答 806
最新判题：needs_review 709 / failed 94 / graded 3
step_results_json 为空：803
其中 raw_response 含 reasoning_steps：709
可恢复评分点链接：1231
可关联学生：40（全部 90 个评分点映射）
```

真实模型返回的是 `reasoning_steps`，而 `validate_llm_result()` 只读取 `step_results`：

```python
if "step_results" not in result and isinstance(result.get("steps"), list):
    result["step_results"] = result["steps"]
```

模型原始响应被完整保存，但解析阶段没有使用 `reasoning_steps`，导致：

- 709 条虽然模型已给出步骤/操作/评分点/知识关联，入库时 `step_results=[]`；
- 校验器认为“未处置评分点、步骤满分为 0”，全部标记 `needs_review`；
- `grade_usage()` 按设计排除 `needs_review`，所以学情证据为 0；
- 学生/班级画像全部“证据不足”。

这不是知识点映射或统计公式问题，而是**判题响应字段别名未识别**。

## 2. 已完成的代码修复

文件：`xueban-backend/xueban/api/xueban_teacher.py`

1. `validate_llm_result()`：
   - 优先 `step_results`；
   - 当 `step_results` 缺失或为空时，使用 `reasoning_steps`，其次 `steps`；
   - 记录 `step_results_alias` 便于追溯。

2. `build_source_steps()`：
   - 无解题过程但有最终答案时，生成 `final_answer` 类型的 source_step；
   - 填空/选择等题型可以把评分点证据定位到最终答案，而不是凭空造步骤。

3. 单 source 且为 `final_answer` 时，允许 reasoning step 的 `source_step_id` 为空并绑定该 source；过程题仍要求明确映射。

测试：`test_step_structure.py` 新增 `test_final_answer_reasoning_steps_alias_is_accepted`，使用真实模型形态的 `reasoning_steps` + 字符串评分点链接，验证：
- `step_results_alias == "reasoning_steps"`；
- source 绑定 `src-1`；
- 评分点 awarded=1.0；
- 无 review 问题。
