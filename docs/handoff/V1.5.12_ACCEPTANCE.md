## 2. 根因、修改与代码位置

| 问题 | 根因 | 修改 | 位置 |
| --- | --- | --- | --- |
| v4 角色/审计/版本非原子 | 分离 UPDATE/INSERT，版本最后登记 | 单版本事务包裹角色、审计、版本 | `_apply_migration`、`_migration_v4` |
| v5 回填非原子 | 回填与版本登记分离 | 同一事务 | `_migration_v5`、`_apply_migration` |

| 失败不可查询 | 无记录表/状态 | `schema_migration_failures` + 状态接口 + CLI | `bootstrap`、`/migrations/status`、`scripts/migration_status.py` |
| 迁移未完成仍可访问教师接口 | 无状态门槛 | running/failed 返回 503 | `teacher_resource_scope_guard` |
| 图边/兼容记录可跨教师操作 | 只校验路径参数，body batch 未校验 | candidates/add/delete 边校验 batch；version-compat 绑定 batch | 对应端点 |
| 方法机会变更后残留 | 只插入不删除 | 重算同步（删除 stale、更新状态/权重） | `generate_method_opportunities` |

## 3. v4/v5 迁移事务设计

```python
def _apply_migration(version, fn):
    with db.transaction():                 # BEGIN IMMEDIATE
        if db.q1("SELECT version FROM schema_migrations WHERE version=?", (version,)):
            return False                   # 已执行，跳过
        fn()                               # 角色/审计/enrollment/版本登记
        db.x("INSERT INTO schema_migrations ...")
    return True
```

- 每版本独立提交；v4 的角色修改、审计、版本登记同事务；v5 的 enrollment 回填与版本登记同事务。
- 失败：该版本整体 rollback；`schema_migration_failures` 在事务外记录失败版本与脱敏原因；进程状态 `failed`。
- 重试：从失败版本继续；已成功版本不重跑。
- 并发：`BEGIN IMMEDIATE` 串行化写事务，版本检查在事务内，不依赖进程锁。
- 不删除历史表，不重建业务表（v1 仅按唯一约束变化重建 `teacher_answers`，列数据原样复制）。
