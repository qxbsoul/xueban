## 2. 全链路审计

| 环节 | 表/函数 | 主键/关联 | 状态/口径 |
|---|---|---|---|
| CSV 导入 | `teacher_import_files`, `teacher_batches`, `teacher_answers` (`import_rows`) | batch_id, student_id, question_id, event_id+revision 唯一 | 未作答/空值/版本缺失在此进入 |
| 预处理 | `teacher_data_issues` (`_build_issues`) | task_id + issue_key + answer/question | 互斥主状态 + 问题处理状态 |
| 判题任务 | `teacher_grade_jobs` (`batch()`, `_run_job_once`) | job.batch_id；item.job_id+answer_id | queued/running/pausing/paused/retrying/completed/failed |
| AI 判题 | `teacher_grade_runs` (`grade_answer`) | answer_id + grading_version 唯一 | graded/needs_review/failed/manual_corrected |
| 步骤/评分点 | `grade_runs.step_results_json` | step.scoring_point_links[].scoring_point_id | 只接受题目原始评分点 |
| 评分点配置 | `scoring_points` | code `QxxxPn`，batch_id | 90 个 |
| 知识点映射 | `scoring_point_knowledge_links` | scoring_point_id → knowledge_point_id | 90 条，全部 legacy_indicator |
| 学情证据 | `learning_analysis._evidence` | 最新事件 + 最新判题 + 可用评分点 | 1274 行，40 学生 |
| 聚合 | `class_profile` / `student_profile` | student_id 去重；class_id 过滤 | 单任务/全部任务 |

**关键状态口径**：`graded` / `manual_confirmed` 可计分且评分点证据有效；`manual_corrected` 只有逐点确认后证据有效；`needs_review`、`failed` 不计分也不计证据；`pending` 无判题。`failed` 是执行失败，不是“作答错误”。

**已确认的排除点**：
- 同一学生同一事件同一题多修订只取最新（7 组，806→799）。
- `needs_review` / `failed` / 未逐点确认的人工修正排除。
- 评分点无知识点映射、分值越界、步骤不可定位的单个证据排除。
- 班级聚合按 class_id 过滤；全部任务合并底层证据，不平均各任务均值。

## 3. 根因

### 3.1 原始作答缺失
- `batch()` 以前把所有 `grading_status='pending'` 的作答都投给模型，包括答案/过程都空、明确未提交、占位符；到模型阶段才由 `grade_answer` 抛 `answer_missing`，被当成普通判题失败。
- 预处理虽区分 `explicit_unsubmitted` / `empty_answer_unknown`，但没有阻断投递。

### 3.2 复核率高
46 条复核实际全部来自**非关键校验告警**：
`scoring_point_awarded_capped`（模型重复给分，已截断到满分）、`step_score_do_not_close`（已按步骤合计修正）、`reasoning_step_without_source`/`operation_without_source`（来源定位缺失）、`step_links_ignored`（已以操作级为准）、`scoring_point_declared_max_clamped`、`scoring_point_allocation_exceeds_total`。
旧逻辑把任何 `severity=review` 都升级为整题复核，导致 41 条本可自动判定的记录进入复核；只有 5 条 `scoring_points_do_not_close`（评分点合计与总分仍无法闭合）属于关键不确定。

用户看到的“70%”更接近**重判子集**：v1.5.21 的 37 条重判中有 31 条复核（84%）；整体 46/806=5.7%。修复后整体 5/806=0.62%。

### 3.3 有效学生少
- 不是映射缺失：90/90 评分点都有知识点映射，0 未映射。
- 不是重复计数：按 student_id 去重；DC01 21 人、DC02 19 人。
- 是**知识点机会题覆盖不足**：
  - `kp:T01I3` 只有 2 道机会题，13 人有任意证据，但只有 1 人两题都有足够证据，达到 `MIN_EVIDENCE=2`/`MIN_QUESTIONS=2` 的只有 1 人。
  - `kp:T03I3` 4 道机会题，14 人有任意证据，只有 2 人达到门槛。
- 映射全部是 `legacy_indicator` 单映射（每题所有评分点映射到该题 indicator），不是未映射；要提高粒度需要真实知识点映射，不能强行拆分。
- 46 条复核被排除进一步减少了证据：修复后 41 条转为自动，证据行 1180→1274。

## 4. 修复内容

1. **未作答/缺失提前阻断**：`pending_answer_ids()` 排除明确未提交、空答案+空过程、纯占位符；新增 `placeholder_answer` 问题；未作答不调用模型，缺失不写成 `failed`。
2. **复核分级**：只保留 4 个关键复核码：
   `scoring_points_sum_mismatch`、`scoring_points_do_not_close`、`process_without_steps`、`global_question_fallback`。
   其他确定性可修复问题降为结构化告警，仍保留原始证据。
3. **结构化复核记录**：`job()` 返回 `reviews[]`，含 reason_codes、具体原因、学生/题目/版本、AI 得分、满分；`structure_json` 存 `review_reasons`。
4. **任务级审计**：`GET /batches/{id}/data-audit` 输出原始/正常/未作答/缺失/占位符/最新判题状态/评分点/已映射/证据行/学生数，单位明确。
5. **旧复核归并**：`POST /batches/{id}/reclassify-reviews`（dry_run）只归并非关键告警，关键 5 条保留；实际执行 41 条自动、5 条保留。
6. **覆盖明细**：每个知识点返回有证据学生、达到门槛学生、有效证据行、有效作答、有效评分点、覆盖率和机会题（已覆盖/总机会）；前端抽屉解释为什么“有证据学生多、达到门槛少”。
7. **班级证据过滤**：`class_profile` 单任务证据按 `class_id` 过滤，避免把另一班证据算进覆盖率（修复前 `evidence_coverage` 可能 >1）。

## 7. 未完成/风险

1. **1 条最终失败是 answer_missing**：原始作答/过程为空，属于数据缺失，不能判题；不伪造成成功。
2. **5 条复核保留**：评分点合计与总分不闭合，没有可靠自动修正依据；需人工确认。
3. **T01I3/T03I3 覆盖仍低**：机会题只有 2/4 道，属于赛题数据范围；不能通过降低 `MIN_QUESTIONS`/`MIN_EVIDENCE` 或强行映射提高。
4. **90 条映射全部 legacy_indicator**：每题所有评分点映射到同一 indicator，粒度粗；需要教师确认更细知识点映射，未强行拆分。
5. **5 条明确未作答仍留在历史 job 806 中**（旧任务已运行）；新任务选择已排除，历史失败/完成记录未删除。
6. **数据审计尚未做前端独立页面**：已提供 API 与任务页可调用能力；本次未新增完整审计 UI。
