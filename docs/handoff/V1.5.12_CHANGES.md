# v1.5.12 变更说明：迁移安全加固与验收准备

基线：v1.5.11 `1079e58`。本版本不新增业务功能，重点在迁移原子性、失败可观测、权限补充审计与真实验收材料。

## P0 迁移原子性与失败处理

### 问题

- v4 的角色 UPDATE 与审计 INSERT 分离，且版本登记在两者之后；中途异常会留下“角色已改、审计缺失、版本未登记”。
- v5 回填与版本登记同样不在同一事务。
- v1 迁移内部手工 `BEGIN IMMEDIATE/COMMIT`，与其他事务组合时存在重复 BEGIN/提前 COMMIT 风险。
- 启动钩子捕获异常只记 warning，服务继续启动。
- 没有失败版本/失败原因的可查询状态。

### 修改

- 新增 `_apply_migration(version, fn)`：单版本独立 `db.transaction()`，事务内检查版本→执行→写 `schema_migrations`，异常整体回滚。
- 每个版本拆成 `_migration_v1..v5`；v4 的角色修改、审计、版本登记同事务；v5 回填与版本登记同事务。
- `migrate_answer_scope()` 改为 `with db.transaction()`，不再手工 BEGIN/COMMIT。
- 新增 `schema_migration_failures(id, version, error, failed_at)`；失败记录在回滚事务之外写入，保留失败版本与脱敏原因。
- `bootstrap()` 失败后设置进程状态 `failed` 并 `raise`；`server.py` 启动钩子记录 error 后重新抛错，服务**不会**在迁移失败状态继续监听。
- 中间件在 `running/failed` 状态对教师业务接口返回 503 `MIGRATION_NOT_READY`；`/api/teacher/migrations/status` 公开只读（脱敏）。
- 错误信息脱敏：密码/token/secret/api_key 值替换为 `***`，`sk-` 前缀 key 替换。
- 逐步执行、重复启动：事务内查版本，成功后不重跑；v5 `INSERT OR IGNORE` + 唯一键。
- `SCHEMA_VERSION=5`；`init()` 仍只补表/列，不执行历史迁移。

## P0 正式库预演

- 新增只读脚本：
  - `scripts/migration_preflight.py`：路径、大小、mtime、SHA、integrity、版本、角色、guest 不一致、缺失/未知 role、批次/owner、作答、enrollments、所需表列、WAL。
  - `scripts/migration_status.py`：服务未启动时读取已完成/失败版本。
  - `scripts/migrate_copy.py`：复制正式库→副本迁移→前后对照→重复执行→失败注入/重试；不写源库。
- 正式库只读基线、副本迁移、失败回滚、恢复方案见 `V1.5.12_MIGRATION_REPORT.md`。
- **正式库未执行迁移**，未启动会自动迁移的服务；等待确认。

## P1 验收材料

- `scripts/export_grading_sample.py` 增强：
  - 增加批次/日期/参考答案/参考解法/evaluable 标记；
  - 覆盖正确、部分正确、错误、needs_review、缺过程、pending；
  - 去重、缺参考答案/题面/满分/作答统计；
  - 人工模板增加评分点命中、证据准确性、复核判断。
  - 仍只读，不调用模型。
- 新增 `scripts/export_mapping_checklist.py`：导出 90 条真实映射审核清单，含决策/权重/依据列；不自动确认。
- 新增 `scripts/export_pending_issues.py`：导出 9 条 pending issue，含类型、原始数据、建议动作、影响；不删除、不改 accepted。
- 方法机会生成改为“重算同步”：删除已不存在的映射机会，更新状态/权重，按 `(batch, question_version, method)` 唯一计数，不跨题目版本复用。
- 权限补漏：
  - 知识依赖候选/新增边校验 `batch_id` 归属；
  - 删除边按 edge 的 batch 校验归属；
  - `version-compat` 必须绑定当前教师任务，新增 `batch_id` 列并按任务过滤；
  - 全局 legacy 评分点禁止直接改写（只能读取）。
- 新增测试：`test_migration_atomicity.py`（原子/回滚/重试/状态/启动失败/脱敏）、权限路由全覆盖鉴权测试、方法机会同步测试。

## 数据库变化

- 新表：`schema_migration_failures(id, version, error, failed_at)`。
- 新列：`teacher_version_compat.batch_id`（ensure_model 时自动 ALTER）。
- 迁移 v4/v5 行为修正，但已有 v4/v5 的库不会重跑；新库/旧库首次执行获得原子保证。
- 不删除/不重建业务表，不改历史业务数据。

## 接口变化

- 新增 `GET /api/teacher/migrations/status`（无需登录；只返回状态/版本/脱敏错误，不返回数据或数据库路径）。
- `POST /api/teacher/version-compat` 新增必填 `batch_id`，并校验任务归属。
- 迁移未完成时教师业务接口返回 503。
