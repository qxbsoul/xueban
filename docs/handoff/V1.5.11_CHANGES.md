# v1.5.11 变更说明（数据安全、学情可信度、真实业务闭环）

基线：v1.5.10 `be74df5`。本版本以修复权限边界、统计口径和历史追溯为主，未引入新基础设施。

## P0 权限与数据安全

### P0-1 游客账号被当作教师

- 现象：`auth_type=guest` 的账号 `role` 为空，登录后 `teacher()` 的默认值把空角色当成教师；真实库 46 个游客账号全部 `role='teacher'`。
- 根因：`xueban_auth.guest()` 插入时未写 role；`xueban_teacher.teacher()` 使用 `(role or "teacher") == "teacher"`。
- 修改：游客创建显式写 `role='guest'`；`teacher()` 改为严格白名单；`_public_user` 缺失角色回退 `guest`；登录查询不再把空角色当教师。
- 文件：`xueban/api/xueban_auth.py`、`xueban/api/xueban_teacher.py`。
- 迁移：`schema_migrations v4` 把 `auth_type=guest` 的账号统一收敛为 `guest`；缺失 role 的非游客账号按最小权限处理（已绑定学生档案→student，否则→guest），每条写入 `xueban_account_audit`。**不会**把未知账号升级为教师。
- 测试：`tests/test_permissions_http.py`（8 项，真实 HTTP）。

### P0-2 教师端跨教师资源越权

- 现象：任意教师可读取其他教师导入的任务、作答、判题、学情、学生账号。
- 根因：任务表无归属字段，列表与详情均为全局查询。
- 修改：
  - `teacher_batches.owner_id` 记录导入教师；新任务按 owner 过滤。
  - 中间件 `teacher_resource_scope_guard` 对 `/api/teacher/**` 的 `batch/answer/grade/job/student` 路径参数和 `batch_id` 查询参数统一校验归属；无权与不存在均返回 404。
  - 任务列表、汇总、班级、学生、作答、判题结果、导入记录、审计、成绩、分析默认批次全部按当前教师范围过滤；默认批次改为“当前教师可见的最新任务”。
  - 学生账号查询、重置、绑定、学情、趋势、推荐、知识缺口均校验学生是否出现在当前教师任务中。
  - v1.5.9 及以前 `owner_id` 为空的批次作为“历史共享任务”保留可见；这是兼容策略，已在文档标注，不用于新数据。
- 评分点详情/映射写入同样校验所属批次；全局 legacy 评分点只读，禁止跨任务改写。
- 文件：`xueban/api/xueban_teacher.py`、`xueban/server.py`、`xueban/services/learning_analysis.py`。
- 测试：同上的权限矩阵覆盖跨教师任务/作答/判题/学生、游客真实 ID、学生越权、未登录 401。

### P0-3 游客演示边界

- 游客现在只能使用工作台/学习中心演示空间；教师任务、学生档案、学情、判题接口一律 403。
- 不关闭演示功能，但**不再**提供“游客进入教师端看真实任务”的能力；游客自己的 workspace 仍由 `ensure_company` 独立创建。
- 未登录：教师/学生接口 401，原有公开接口不变。

## P1 学情统计正确性

### P1-1 趋势可比性

- 现象：两次考试只要都有三个版本号就判可比，即使版本不同。
- 根因：`compare_signatures` 只检查版本字段非空，未比较版本值；`node_signature` 未包含算法参数版本与每题版本差异。
- 修改：
  - 版本值必须一致才 comparable；不同版本必须命中 `teacher_version_compat` 的显式兼容记录（kind + 左右版本 + 非空依据），否则 non_comparable。
  - 题目版本逐题比较；缺少版本元数据仍为 unverifiable。
  - 算法版本 `sp-beta-v3`、参数版本纳入签名并参与比较。
  - 学生群体：返回重合人数、左右独有、重合率；重合率 < 80% 给出“总体变化可能受群体变化影响”的警告（不因此判题目不可比）。
  - 前端趋势图：只有相邻且都为 comparable 的点才连线；non_comparable/unverifiable 以空心/虚线点显示并标注原因，不连成平滑曲线。
- 文件：`xueban/services/learning_analysis.py`、`xueban-web/src/components/LearningAnalytics.tsx`。
- 测试：`tests/test_trend_version_gate.py`（4 项）。

### P1-2 方法机会覆盖率

- 现象：`question_count` 与 `opportunity_count` 来自同一集合，覆盖率恒为 100%。
- 根因：没有独立的机会数据模型。
- 修改：
  - 新表 `teacher_method_opportunities`（batch、question_version、question、method、opportunity_type、mapping_status、confidence、source）。
  - 机会由“题目版本评分点→方法映射”生成，不根据学生已用方法反推；评分点方法映射保存后自动生成，也可手动触发。
  - 覆盖率 = 观察到该方法的题目数 / 该任务中该方法的机会题目数；机会为 0 时返回 `null` + `暂不可计算`，绝不显示 100%。
  - 方法状态新增 `暂无证据`（有机会无作答）、`暂不可计算`（缺机会数据）；单题证据集中（>80% 权重）显式标记，且单题证据不能达到确定性掌握。
- 文件：`xueban/services/learning_analysis.py`、`xueban/api/xueban_teacher.py`、前端学生/教师方法表。
- 测试：`tests/test_method_coverage.py`（4 项）。

### P1-3 任务内学生身份

- 现象：学生/班级/考试节点是全局表，同编号跨任务被隐式视为同一人。
- 调查结论：学生账号需要跨任务持续使用；同编号在现有模型中映射到同一 `teacher_students`，不能凭编号证明同一人。
- 修改：
  - 新表 `teacher_enrollments`：每任务每学生的快照（编号、班级、年级、身份状态、依据）。
  - 默认 `identity_status='unverified'`；教师可显式标记 `same_person / distinct / uncertain`，确认必须填依据。
  - 导入时写入快照；v1.5.10 及以前的任务由迁移 v5 从作答回填为 unverified。
  - 跨任务学生趋势返回 `identity_issues` 与 `identity_warning`；未确认身份不宣称同一人。
  - 删除任务只删除本任务快照，不影响其他任务。
- 文件：`xueban/api/xueban_teacher.py`、`learning_analysis.student_knowledge_trend`、前端“任务内学生身份”面板。
- 测试：`tests/test_identity_mapping.py`（6 项中的身份部分）。

### P1-4 映射确认闭环

- 修改：
  - 映射状态区分 `confirmed / legacy / pending_review / rejected / unmapped`；拒绝保留记录而非删除。
  - 每次确认/拒绝生成新的 `teacher_mapping_versions` 版本；历史表记录 confirm/reject 与前后值。
  - 判题结果写入 `mapping_version`；学情快照写入版本并参与快照哈希（映射变化必产生新快照）。
  - 新增 `GET /batches/{id}/mapping/impact` 识别旧版本判题与旧快照。
  - 映射列表支持按知识点筛选。
- 测试：`tests/test_identity_mapping.py` 映射部分。

## P2 真实业务验证与反馈

### P2-1 错误分类评价

- 新表 `error_label_gold` 保存人工标注（与规则/模型标签分表）。
- `GET /batches/{id}/error-labels/metrics` 计算多标签 precision/recall/F1、macro-F1、无法判断比例；没有人工标注时不伪造指标。
- 接口：`POST /answers/{id}/error-labels/gold`；答案标签接口同时返回 gold。

### P2-2 推荐反馈闭环

- 新表 `recommendation_feedback`：推荐类型、目标、理由、证据、状态、完成时间、followup。
- 接口：创建反馈、标记完成、按学生/任务查询。
- 不引入复杂推荐模型，只保证推荐可追溯、可评价。

### P2-3 后台任务可靠性

- 抽取 `recover_stale_jobs()`：心跳超过 5 分钟的 running/pausing 任务恢复为 paused，running item 归还 pending；bootstrap v3 调用。
- 同一进程内 `run_job` 按 job 加锁，避免共享 SQLite 连接被两个 worker 并发写；跨进程仍依赖 item 原子领取。
- 双 worker 并发测试证明同一 job 只被一个 worker 执行，item 不重复判题；`processed=completed+failed` 与 item 状态一致。

## 算法与接口变化

- `ALGORITHM_VERSION=sp-beta-v3`，参数版本记录方法机会口径。
- `GRADER_VERSION=v1.5.11`，提示词版本仍为 `teacher-grade-v3`。
- 新增接口：enrollments、method-opportunities、mapping/impact、version-compat、error-labels/gold+metrics、recommendation feedback。
- 权限：`/api/teacher/**` 除 `grade/config` 外统一要求登录并按资源归属校验。
